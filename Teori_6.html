Penyimpanan Data Lokal: SharedPreferences

Data yang diketik pengguna jangan hilang saat aplikasi ditutup. Kenali penyimpanan kunci–nilai paling sederhana di Android, lalu terapkan lewat studi kasus Aplikasi Pengaturan Profil langkah demi langkah.

Materi 01

Kenapa Data Bisa Hilang?

Bayangkan pengguna mengisi nama dan email di aplikasi kamu, menekan Simpan, lalu menutup aplikasi. Saat dibuka lagi — semua isian kosong kembali. Ini bukan salah tampilan, melainkan karena data hanya disimpan di memori.

Variabel biasa hidup hanya selama aplikasi berjalan

var nama = "Rani Putri"   // disimpan di memori (RAM)

Selama aplikasi terbuka, nilainya bisa dibaca kapan saja. Begitu aplikasi ditutup, memori dibersihkan dan nilai itu hilang. Supaya tetap ada, nilainya harus ditulis ke penyimpanan — salah satu caranya dengan SharedPreferences.

Aplikasi berjalan variabel di memori: nama, email, bio ada selama aplikasi terbuka
Simpan →edit().apply()
profil_prefs.xml di penyimpanan internal tetap ada walau aplikasi ditutup
Muat →getString()
Aplikasi dibuka lagi isian langsung terisi data lama dibaca di onCreate()

Kapan data hilang, kapan tetap ada

KejadianVariabel di memoriData di SharedPreferences
Menekan tombol Back untuk keluarHilangTetap
Aplikasi ditutup paksa (digeser dari daftar aplikasi terakhir)HilangTetap
Ponsel dimatikan lalu dinyalakan lagiHilangTetap
Pengguna menekan Clear data di pengaturan aplikasiHilangTerhapus
Aplikasi di-uninstallHilangTerhapus
Inti bagian ini: kalau data harus tetap ada setelah aplikasi ditutup, jangan hanya disimpan di variabel — tulis ke penyimpanan.
Materi 02

SharedPreferences Itu Apa?

SharedPreferences adalah penyimpanan sederhana berbentuk pasangan kunci–nilai (key–value). Satu data disimpan dengan nama (kunci), dan dibaca kembali memakai nama itu.

Analoginya: label gantung

Bayangkan kotak penyimpanan dengan banyak label: “nama”, “email”, “mode_gelap”. Untuk menaruh data, kamu menulis nama labelnya; untuk mengambil data, kamu menyebut nama label yang sama.

Kunci (key)Nilai (value)Tipe
namaRani PutriString
emailrani@example.comString
avatar1Int
mode_gelaptrueBoolean

Di mana datanya disimpan?

Android menyimpannya sebagai satu file XML di penyimpanan internal aplikasi. Kita tidak perlu menulis file itu sendiri — Android yang mengurus. Bentuk isinya seperti ini:

<!-- /data/data/com.example.pengaturanprofil/shared_preferences/profil_prefs.xml -->
<?xml version='1.0' encoding='utf-8' standalone='yes' ?>
<map>
    <string name="nama">Rani Putri</string>
    <string name="email">rani@example.com</string>
    <boolean name="mode_gelap" value="true" />
    <int name="avatar" value="1" />
</map>
Mau membuktikan sendiri? Jalankan aplikasi di emulator, lalu buka View → Tool Windows → Device File Explorer dan telusuri data/data/nama.package.aplikasi/shared_preferences/. File XML di atas akan terlihat persis seperti isi datamu.

Kapan dipakai — dan kapan jangan

Cocok dipakai untukJangan dipakai untuk
Pengaturan aplikasi: mode gelap, bahasa, notifikasiData besar: gambar, video, daftar panjang
Profil singkat pengguna: nama, email, bioData berbentuk tabel yang perlu dicari/diurutkan
Penanda sederhana: “sudah pernah membuka aplikasi”, status loginData rahasia: password, token, nomor kartu
Skor tertinggi atau jumlah percobaan pada gameData yang dipakai bersama beberapa pengguna
Inti bagian ini: SharedPreferences paling pas untuk data kecil dan sederhana. Kalau datanya banyak atau berstruktur, pakai database seperti Room.
Perhatian: isi SharedPreferences tidak terenkripsi. Siapa pun yang punya akses ke perangkat root bisa membacanya. Jadi jangan pernah menyimpan password atau token di sini.
Materi 03

Mengambil Objeknya & Tipe Data yang Didukung

Langkah pertama: ambil objek SharedPreferences

val prefs = getSharedPreferences("profil_prefs", MODE_PRIVATE)
BagianArti
"profil_prefs"Nama file penyimpanan. Bebas ditentukan sendiri — satu aplikasi boleh punya beberapa file.
MODE_PRIVATEHanya aplikasi kita yang bisa membaca file ini. Selalu pakai mode ini.
getSharedPreferences(...)Method milik Context, jadi bisa dipanggil dari dalam Activity. Objeknya dibuat sekali, lalu dipakai berulang.
Ada juga: getPreferences(MODE_PRIVATE) memakai nama kelas Activity sebagai nama file, dan getDefaultSharedPreferences() memakai file bawaan PreferenceManager. Untuk belajar, selalu pakai getSharedPreferences() supaya nama filenya jelas.

Tipe data yang bisa disimpan

TipeMenyimpanMembacaContoh isi
TeksputString("nama", "Rani")getString("nama", "")nama, email, bio
Angka bulatputInt("avatar", 1)getInt("avatar", 0)pilihan avatar, skor
Angka panjangputLong("waktu", 0L)getLong("waktu", 0L)waktu simpan terakhir
Angka desimalputFloat("rasio", 1.5f)getFloat("rasio", 1f)ukuran huruf
Ya / tidakputBoolean("mode_gelap", true)getBoolean("mode_gelap", false)sakelar pengaturan
Kumpulan teksputStringSet("tag", setOf("a"))getStringSet("tag", emptySet())daftar favorit singkat

Menulis harus lewat Editor

Objek SharedPreferences hanya bisa dibaca. Untuk menulis, ambil Editor-nya dulu, isi nilainya, lalu simpan.

val editor = prefs.edit()          // 1) ambil editor
editor.putString("nama", "Rani Putri")  // 2) isi nilai
editor.apply()                      // 3) simpan ke penyimpanan
MethodCara kerjaDipakai kapan
apply()Menyimpan di belakang layar (asinkron), tidak mengembalikan nilaiGunakan ini — aplikasi tidak tersendat
commit()Menyimpan saat itu juga, mengembalikan true/falseHanya bila hasil simpan perlu diperiksa langsung
Kesalahan paling sering: menulis prefs.edit().putString(...) lalu berhenti di situ. Tanpa apply(), tidak ada satu pun data yang tersimpan — dan tidak ada pesan error apa pun.
Materi 04

Pola Tetap: Menyimpan & Membaca

Hampir semua pemakaian SharedPreferences mengikuti dua pola yang sama. Hafalkan bentuknya, tinggal ganti nama kunci dan tipe datanya.

Pola Menyimpan — 3 langkah

  1. Ambil objek prefs
  2. edit() → put...
  3. apply()

Pola Membaca — 1 langkah

  1. getString(KUNCI, default)
  2. Pakai nilainya untuk mengisi tampilan
// ---------- MENYIMPAN ----------
val prefs = getSharedPreferences("profil_prefs", MODE_PRIVATE)

prefs.edit()
    .putString("nama", "Rani Putri")
    .putBoolean("mode_gelap", true)
    .apply()                     // jangan pernah lupa baris ini

// ---------- MEMBACA ----------
val nama  = prefs.getString("nama", "") ?: ""       // default: teks kosong
val gelap = prefs.getBoolean("mode_gelap", false)   // default: mati
Rangkaian put boleh disambung. edit() mengembalikan Editor, dan setiap put... juga mengembalikan Editor yang sama — jadi bisa ditulis berantai dan cukup satu apply() di akhir.

Nilai default: kenapa penting?

Saat aplikasi baru dipasang, belum ada data sama sekali. Kalau dibaca begitu saja, hasilnya kosong dan tampilan bisa rusak. Karena itu setiap get... wajib diberi nilai default yang masuk akal:

TipeNilai default yang wajar
String"" (teks kosong) atau "Belum diisi"
Int / Long0 atau 1
Float0f
Booleanfalse (pengaturan mati di awal)
Set<String>emptySet()
Kunci harus sama persis. Menyimpan dengan kunci "nama" lalu membaca dengan "Nama" akan menghasilkan data kosong tanpa pesan error — persis seperti masalah nama kunci Extra pada Intent. Karena itu kunci sebaiknya disimpan sebagai const val.
Inti bagian ini: menyimpan = edit() → put → apply(). Membaca = get... dengan nilai default. Dua pola inilah yang dipakai berulang di studi kasus berikut.

Materi 07

Langkah 5–6: Kunci Data & Menyimpan

5

Tentukan Nama File & Kunci

Semua nama sebaiknya ditulis sekali saja di bagian atas kelas. Kalau kunci ditulis langsung di banyak tempat, cepat atau lambat pasti ada satu yang salah ketik — dan datanya jadi tidak terbaca.

class MainActivity : AppCompatActivity() {

    companion object {
        // nama file penyimpanan (bebas, terserah kita)
        private const val NAMA_PREFS = "profil_prefs"

        // kunci datanya
        private const val KEY_NAMA   = "nama"
        private const val KEY_EMAIL  = "email"
        private const val KEY_BIO    = "bio"
        private const val KEY_AVATAR = "avatar"
        private const val KEY_GELAP  = "mode_gelap"

        // tiga pilihan avatar (urutan sesuai tombol Ganti Avatar)
        private val DAFTAR_AVATAR = listOf(
            R.drawable.avatar_1, R.drawable.avatar_2, R.drawable.avatar_3
        )
    }

    // objek SharedPreferences dibagikan ke seluruh kelas
    private val prefs by lazy { getSharedPreferences(NAMA_PREFS, MODE_PRIVATE) }

    private var indeksAvatar = 0      // 0, 1, atau 2

    // ... view dan fungsi-fungsinya ditulis pada langkah berikutnya ...
}
Mengapa by lazy? Supaya objek SharedPreferences dibuat sekali saja, saat pertama kali dipakai, lalu dipakai ulang di semua fungsi. Tidak perlu memanggil getSharedPreferences() berulang kali.
6

Menyimpan Data ke SharedPreferences

Satu fungsi untuk menyimpan semuanya. Perhatikan bahwa semua isian dikumpulkan ke dalam satu rangkaian yang diakhiri apply().

private fun simpanProfil() {
    prefs.edit()
        .putString(KEY_NAMA,   etNama.text.toString().trim())
        .putString(KEY_EMAIL,  etEmail.text.toString().trim())
        .putString(KEY_BIO,    etBio.text.toString().trim())
        .putInt(KEY_AVATAR,    indeksAvatar)
        .putBoolean(KEY_GELAP, swGelap.isChecked)
        .apply()                     // WAJIB: tulis ke penyimpanan

    Toast.makeText(this, getString(R.string.pesan_tersimpan), Toast.LENGTH_SHORT).show()
}

Lalu panggil dari tombol Simpan Profil:

btnSimpan.setOnClickListener { simpanProfil() }

Alur saat tombol Simpan ditekan

BarisYang terjadi
prefs.edit()Membuka sesi penyuntingan pada file profil_prefs.xml
putString(...)Menuliskan isi EditText ke kunci nama, email, bio
putInt(KEY_AVATAR, indeksAvatar)Menyimpan avatar yang sedang dipilih, cukup sebagai angka
putBoolean(KEY_GELAP, ...)Menyimpan posisi sakelar mode gelap (nyala / mati)
apply()Menuliskan semuanya ke penyimpanan, di belakang layar
Kalau apply() terlupa, aplikasi tetap berjalan tanpa error dan tampilan tetap berubah — tetapi setelah aplikasi ditutup, seluruh data kembali kosong. Gejala inilah yang paling sering terjadi saat belajar SharedPreferences.
Hanya berubah, bukan menimpa file. apply() hanya menuliskan kunci yang kamu sebutkan. Kunci lain yang sudah ada di file itu tetap aman — jadi data yang tidak diubah tidak akan hilang.
Materi 08

Langkah 7–8: Membaca, Menerapkan & Menghapus

7

Membaca Data Saat Aplikasi Dibuka

Fungsi ini dipanggil sekali di onCreate(). Tugasnya: mengambil semua nilai dari SharedPreferences, lalu menaruhnya kembali ke tampilan.

private fun muatProfil() {
    // 1) baca semua nilai; default dipakai bila data belum pernah disimpan
    val nama     = prefs.getString(KEY_NAMA, "") ?: ""
    val email    = prefs.getString(KEY_EMAIL, "") ?: ""
    val bio      = prefs.getString(KEY_BIO, "") ?: ""
    indeksAvatar = prefs.getInt(KEY_AVATAR, 0)
    val gelap    = prefs.getBoolean(KEY_GELAP, false)

    // 2) isikan ke tampilan
    etNama.setText(nama)
    etEmail.setText(email)
    etBio.setText(bio)
    ivAvatar.setImageResource(DAFTAR_AVATAR[indeksAvatar])
    swGelap.isChecked = gelap

    // 3) terapkan tampilan yang bergantung pada data tersimpan
    terapkanModeGelap(gelap)
    perbaruiKartu()
}

Panggil di dalam onCreate(), setelah semua view diambil:

override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    setContentView(R.layout.activity_main)

    // ... findViewById & pemasangan listener ...

    muatProfil()      // tampilkan data yang tersimpan (kalau ada)
}
Inilah kunci penyimpanannya. Karena muatProfil() selalu dipanggil saat Activity dibuat, formulir akan terisi sendiri setiap kali aplikasi dibuka — tanpa perlu kode tambahan di mana pun.
8

Menghapus Data & Melengkapi Tampilan

a. Menghapus seluruh data

private fun hapusSemuaData() {
    prefs.edit().clear().apply()      // hapus semua kunci di file ini

    Toast.makeText(this, getString(R.string.pesan_reset), Toast.LENGTH_SHORT).show()
    muatProfil()                      // tampilan kembali ke nilai default
}

Ingin menghapus satu kunci saja? Ganti clear() menjadi remove(KEY_BIO). Keduanya tetap harus diakhiri apply().

b. Mengganti avatar

private fun gantiAvatar() {
    indeksAvatar = (indeksAvatar + 1) % DAFTAR_AVATAR.size   // 0 → 1 → 2 → 0 …
    ivAvatar.setImageResource(DAFTAR_AVATAR[indeksAvatar])
}

Perhatikan: yang disimpan hanya angka indeksnya, bukan gambar. Saat dibaca, angka itu dipakai lagi untuk memilih gambar dari DAFTAR_AVATAR.

c. Menerapkan mode gelap

private fun terapkanModeGelap(aktif: Boolean) {
    val latar      = if (aktif) "#121212" else "#FFFFFF"
    val warnaNama  = if (aktif) "#F5F5F5" else "#1B1B1B"
    val warnaEmail = if (aktif) "#B0B0B0" else "#6B6B6B"

    layoutUtama.setBackgroundColor(Color.parseColor(latar))
    tvNamaKartu.setTextColor(Color.parseColor(warnaNama))
    tvEmailKartu.setTextColor(Color.parseColor(warnaEmail))
}
Ini cara sederhana agar pengaruh data tersimpan langsung terlihat. Untuk aplikasi sesungguhnya, mode gelap sebaiknya memakai tema siang/malam: AppCompatDelegate.setDefaultNightMode() dengan tema Theme.AppCompat.DayNight. Cukup tahu polanya — inti materi kita tetap SharedPreferences.

    private lateinit var etEmail: EditText
    private lateinit var etBio: EditText
    private lateinit var swGelap: SwitchCompat

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        // 1) ambil semua view
        layoutUtama  = findViewById(R.id.layoutUtama)
        ivAvatar     = findViewById(R.id.ivAvatar)
        tvNamaKartu  = findViewById(R.id.tvNamaKartu)
        tvEmailKartu = findViewById(R.id.tvEmailKartu)
        etNama       = findViewById(R.id.etNama)
        etEmail      = findViewById(R.id.etEmail)
        etBio        = findViewById(R.id.etBio)
        swGelap      = findViewById(R.id.swGelap)

        // 2) aksi tombol
        findViewById<Button>(R.id.btnGantiAvatar).setOnClickListener { gantiAvatar() }
        findViewById<Button>(R.id.btnSimpan).setOnClickListener { simpanProfil() }
        findViewById<Button>(R.id.btnReset).setOnClickListener { hapusSemuaData() }

        // 3) kartu profil ikut berubah saat isian diketik
        etNama.doOnTextChanged { _, _, _, _ -> perbaruiKartu() }
        etEmail.doOnTextChanged { _, _, _, _ -> perbaruiKartu() }

        // 4) tampilkan data yang tersimpan
        muatProfil()
    }

    // ================= menyimpan =================
    private fun simpanProfil() {
        prefs.edit()
            .putString(KEY_NAMA,   etNama.text.toString().trim())
            .putString(KEY_EMAIL,  etEmail.text.toString().trim())
            .putString(KEY_BIO,    etBio.text.toString().trim())
            .putInt(KEY_AVATAR,    indeksAvatar)
            .putBoolean(KEY_GELAP, swGelap.isChecked)
            .apply()

        Toast.makeText(this, getString(R.string.pesan_tersimpan), Toast.LENGTH_SHORT).show()
    }

    // ================= membaca =================
    private fun muatProfil() {
        val nama  = prefs.getString(KEY_NAMA, "") ?: ""
        val email = prefs.getString(KEY_EMAIL, "") ?: ""
        val bio   = prefs.getString(KEY_BIO, "") ?: ""
        indeksAvatar = prefs.getInt(KEY_AVATAR, 0)
        val gelap  = prefs.getBoolean(KEY_GELAP, false)

        etNama.setText(nama)
        etEmail.setText(email)
        etBio.setText(bio)
        ivAvatar.setImageResource(DAFTAR_AVATAR[indeksAvatar])
        swGelap.isChecked = gelap

        terapkanModeGelap(gelap)
        perbaruiKartu()
    }

    // ================= menghapus =================
    private fun hapusSemuaData() {
        prefs.edit().clear().apply()
        Toast.makeText(this, getString(R.string.pesan_reset), Toast.LENGTH_SHORT).show()
        muatProfil()
    }

    // ================= tampilan =================
    private fun gantiAvatar() {
        indeksAvatar = (indeksAvatar + 1) % DAFTAR_AVATAR.size
        ivAvatar.setImageResource(DAFTAR_AVATAR[indeksAvatar])
    }

    private fun perbaruiKartu() {
        val nama  = etNama.text.toString().trim()
        val email = etEmail.text.toString().trim()

        tvNamaKartu.text  = nama.ifEmpty { getString(R.string.nama_default) }
        tvEmailKartu.text = email.ifEmpty { getString(R.string.email_default) }
    }

    private fun terapkanModeGelap(aktif: Boolean) {
        val latar      = if (aktif) "#121212" else "#FFFFFF"
        val warnaNama  = if (aktif) "#F5F5F5" else "#1B1B1B"
        val warnaEmail = if (aktif) "#B0B0B0" else "#6B6B6B"

        layoutUtama.setBackgroundColor(Color.parseColor(latar))
        tvNamaKartu.setTextColor(Color.parseColor(warnaNama))
        tvEmailKartu.setTextColor(Color.parseColor(warnaEmail))
    }
}

Materi 10

Ringkasan, Latihan & Tugas

1. Kapan dipakai?

  • Data kecil & sederhana: pengaturan, profil, penanda
  • Bukan untuk data besar, tabel, atau data rahasia

2. Menyimpan

  • getSharedPreferences(nama, MODE_PRIVATE)
  • edit() → putString/putInt/putBoolean → apply()

3. Membaca

  • getString(KUNCI, ""), getBoolean(KUNCI, false)
  • Selalu beri nilai default

4. Menghapus

  • edit().remove(KUNCI) — satu data
  • edit().clear() — seluruh file

Lima kesalahan yang paling sering terjadi

  • Lupa apply() setelah rangkaian put...
  • Menulis kunci "nama" tetapi membaca dengan "Nama"
  • Tidak memberi nilai default saat membaca — muncul null
  • Menyimpan data besar atau data rahasia di SharedPreferences
  • Membaca data sekali di awal, padahal data bisa berubah pada sesi yang sama

Latihan di kelas

  1. Simpan nama panggilan: satu EditText + satu tombol Simpan. Setelah aplikasi dibuka lagi, nama panggilan itu otomatis muncul di TextView.
  2. Tambah satu kunci baru: tambahkan pilihan “kota” pada studi kasus ini lengkap dengan menyimpan, membaca, dan menampilkannya.
  3. Penghitung pembukaan aplikasi: setiap kali aplikasi dibuka, tambahkan 1 ke kunci jumlah_buka, lalu tampilkan “Kamu sudah membuka aplikasi ini n kali”.

Tugas rumah

  • Buat aplikasi Pengaturan Profil sesuai studi kasus ini, dijalankan di emulator atau perangkat asli
  • Wajib memuat minimal 3 tipe data berbeda: String, Int, dan Boolean
  • Wajib ada tombol Simpan dan Hapus Semua Data
  • Kumpulkan tangkapan layar sebelum & sesudah aplikasi ditutup, plus isi profil_prefs.xml dari Device File Explorer
